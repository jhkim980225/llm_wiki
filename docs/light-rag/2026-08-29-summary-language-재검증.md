# SUMMARY_LANGUAGE 수정 후 재검증 — 2026-08-29

[2026-08-29-wiki-색인-질의-테스트.md](2026-08-29-wiki-색인-질의-테스트.md) 3절에서 지적한
"성진" 개체 영문화·분신 문제의 원인(`SUMMARY_LANGUAGE` 미설정 → 기본값 English)을 고쳐
재배포·전량 재색인한 뒤, 실제로 한글 개체명이 뽑히는지 재검증했다.
[파이프라인.md](wiki/파이프라인.md) ⑧단계.

## 조치

`deploy/k8s.yaml`의 `lightrag` Deployment에 `SUMMARY_LANGUAGE: Korean` 추가(커밋
`f118241`). emptyDir이라 재배포 즉시 기존 색인 전부 소실 — wiki 87건 + 기존 34건
총 121건 전량 재색인. 재색인 자체도 halt 사고 2건을 겪고 완전 순차 방식으로 복구
완료(상세는 [운영.md](운영.md) 색인 이력).

## 검증 1 — 무결성 (개수·중복)

```
전체 문서 수: 121   고유 file_path 수: 121   중복: 0
```

wiki 87건은 로컬 대조(그래프 누락·중복·길이·제목)까지 별도로 전수 확인 — 전부 정상.

## 검증 2 — 라벨: "성진" 표기가 한글 중심으로 정리됨

전체 라벨 2,513개 중 "seongjin"/"성진" 포함 66개. 이전(2026-08-25 관찰, SUMMARY_LANGUAGE
수정 전)엔 70여 개 중 **영문 표기가 다수**(Seongjin, Seongjin CEO, Seongjin Employee,
seongjin 등)였는데, 이번엔 핵심 개체명이 전부 한글로 뽑혔다.

```
(주)성진 / (주)성진 R&D / 성진 / 성진 대표이사 / 성진 사업자등록증 회신 /
성진 위탁생산 관련 계약서 / 주식회사 성진 / 성진 주식회사 ...
```

66건 중 나머지는 이메일 제목이 그대로 개체로 잡힌 것(`[성진] 발주서 송부의 건` 등,
2026-08-25 관찰과 같은 패턴, 이번 검증 범위 밖)과, 사람 이름 우연 일치(`박성진`,
`추성진` — 동명이인 여부 미확인, 이번 범위 밖)다.

## 검증 3 — 잔존 영문 라벨 3건: SUMMARY_LANGUAGE와 무관

`Seongjin` · `seongjin` · `seongjin 홈페이지` 3건이 남아 있어 원인을 추적했다.
`/graphs?label=` 조회 결과 전부 `file_path`가 `wiki/entities/*.md`(gd-chem, glowme,
barunweb 등)였고, 해당 문서들을 grep해보니 원인은 하나였다:

```
바른웹은 홈페이지 제작업체다. 2021년 2월 주식회사 [[seongjin]]의 홈페이지를 제작
```

`TEMPLATE.md` 규칙대로 다른 문서를 가리킬 때 `[[id]]`(영문 slug)를 쓰는데, 시드
스크립트가 이 위키링크 구문을 그대로 색인에 넘겨서 본문에 영문 토큰 `seongjin`이
그대로 노출된다. LUNA가 이 리터럴 영문 토큰을 "성진"과 별개 개체로 뽑은 것 —
**LLM이 한글을 영어로 번역한 게 아니라, 원문 자체에 박힌 영문 문자열을 그대로
읽은 것**이라 SUMMARY_LANGUAGE로는 못 막는다. (참고: 2026-08-29 앞선 리포트 2절에서
"위키링크 오염 없음"이라 판단했던 건 5건 표본에서 `seongjin` 자체를 색인하지
않았기 때문 — 표본이 늘며 드러난 케이스.) 범위 밖이라 이번엔 손대지 않음, 필요하면
색인 전 `[[id]]` → 표시용 한글명 치환을 시드 스크립트에 추가하는 방향.

## 결론

SUMMARY_LANGUAGE 수정은 목적대로 작동한다 — 핵심 개체명·질의 응답이 한글로
나온다. 잔존 이슈(이메일 제목이 개체로 잡히는 문제, `[[id]]` 링크 텍스트 오염,
`박성진`/`추성진` 동명이인 여부)는 전부 이번 수정과 무관한 별개 사안이라 범위
밖에 남겨둔다.
