# 위키 문서 리뷰 규칙

[파이프라인.md](파이프라인.md) ⑤단계(`status: draft` → `reviewed`) 게이트 기준. `reviewed`인
문서만 색인 대상이라, 여기를 통과 못 하면 LightRAG에 안 들어간다.

## 검토 항목 5개

### 1. 사실 검증 (원본 대조) — **88개 전수**

문서 내용이 원본 이메일과 맞는지 확인한다. 대부분은 내가 원문을 직접 안 읽고
Explore 에이전트 요약 → 재요약을 거쳐 만든 전언(hearsay) 2단계짜리라 오류가
섞였을 수 있다 — 표본이 아니라 전수를 본다.

- `source_file`에 구체 경로가 있으면 그 파일을 직접 연다
- 폴더 경로(`.../Files/`)만 있으면, 문서에 나온 담당자명·이메일 도메인으로 원문을
  찾아 최소 1건 대조한다 (`docs/light-rag/wiki/data/sj-help_보낸메일함/Files/`에서
  검색)
- 대조해서 틀린 사실은 고치고, 확인 못 한 사실은 문장을 지우거나 "확인 필요"로
  남기지 않는다 — 애매하면 [이슈/](이슈/README.md)에 기록

### 2. `entities:` 정답지 검증 — 기계적 스캔

people/orgs/items 값이 본문에 **문자 그대로(부분문자열)** 등장하는지 확인한다.
TEMPLATE.md 규칙(fuzzy 매칭 없음)이 실제로 지켜졌는지 보는 것 — 안 지켜지면
LightRAG 추출 품질 대조용으로 못 쓴다.

### 3. 이슈 대조 — 기계적 스캔

이 문서 id가 [이슈/](이슈/README.md) 안 어느 파일의 `related`에 걸려 있는지
확인한다. 걸려 있고 `status: open`이면, 문서 본문의 서술이 그 미확정 상태를
정확히 반영하는지 본다 (섣불리 확정 서술로 바뀌어 있으면 안 됨).

### 4. 작성 규칙 준수 — 기계적 스캔

- 한국어 전용 — 영문 개체명 없는지 (번역해서 만든 이름 금지)
- 날짜는 본문에 한국어 표기("2021년 3월 15일")
- 2,000자 이내
- 인사말·서명·주소·전화 블록 같은 노이즈가 본문에 안 들어갔는지

### 5. 링크 정합성 — 기계적 스캔

`[[id]]`가 가리키는 문서가 실존하는지 `Glob`으로 확인한다. 없으면:
- 아직 안 만든 개체를 가리키는 의도된 forward link인지 (템플릿이 허용하는 패턴)
- 오타·id 불일치인지

구분 안 되면 이슈로 남긴다.

## 처리 순서

기계적으로 판별되는 2·4·5를 먼저 배치로 스캔해 위반 목록을 뽑고, 그다음 1(원본
대조)을 88개 전수로 돌며 동시에 3(이슈 대조)도 확인한다. 통과한 문서만
`status: reviewed`로 바꾼다. 걸린 문서는 고쳐서 재검토하거나, 판단이 안 서면
`draft`로 남기고 이슈에 기록한다.
