# LLM Wiki 문서 템플릿

LightRAG 테스트용 `wiki/` 문서의 표준. Claude가 원문(`corpus/` 이메일·제품 자료 등)을 읽고
이 규칙대로 문서를 생성한다.

## 파일 경로

```
wiki/{종류}/{doc_id}.md
```

| 종류 | 담는 것 |
|---|---|
| `entities` | 회사 · 사람 · 부품 · 제품 |
| `sources` | 원문 요약 (이메일·문서 1건 단위) |
| `concepts` | 정책 · 개념 |

`doc_id`: 소문자·숫자·하이픈만 (예: `airwell-a1`, `sunfine-global`).

## 프론트메터 (전부 필수)

```yaml
---
id: airwell-a1                    # 파일명과 일치
title: 에어웰 A1                  # 본문 # 제목과 일치, 한국어
doc_type: entities                # entities | sources | concepts — 폴더와 일치
source_file:                      # 원문 경로 리스트 (하나여도 리스트)
  - corpus/raw/product-airwell-a1.txt
created: 2026-08-26               # YYYY-MM-DD 최초 생성일
updated: 2026-08-26               # YYYY-MM-DD 마지막 내용 수정일
tags: [product, living-appliance] # 분류 태그 리스트
status: draft                     # draft | reviewed
entities:                         # 개체 정답지 — 색인 후 추출 품질 대조용
  people: []
  orgs: []
  items: []
---
```

프론트메터는 기계용이다. **색인 시 통째로 제거**하고 본문만 보내므로, 검색돼야 할 사실은
반드시 본문에 한국어로 쓴다.

`entities` 값은 **본문에 문자 그대로 등장**해야 한다 (fuzzy 매칭 없이 부분문자열 대조).
모르면 빈 리스트, 추정 채움 금지.

## 본문 구조

```markdown
# {title}

{요약 2~3문장 — "X는 …이다"로 시작. 첫 문장이 벡터 검색의 얼굴이다}

## 핵심 사실
- {불릿 — 날짜는 "2026년 7월 15일" 한국어 표기}
- {사람은 성명+직함+소속 세트: 정아라 연구원 (버블뱅크)}

## 관련 문서
- [[sunfine-global]]
- [[order-20260715]]
```

## 링크 규칙

본문에 **다른 문서의 제품명·회사명·사람 이름이 나오면 `[[id]]` 형태로 링크**한다.
표시 텍스트가 다르면 `[[id|표시명]]`. 링크 대상 문서가 아직 없어도 걸어둔다 —
나중에 만들 문서의 표시다.

## 작성 원칙

근거는 [2026-08-25-청킹-인덱싱-관찰.md](../2026-08-25-청킹-인덱싱-관찰.md) 실측.

1. 전부 한국어. 개체명 번역 금지 (영문 개체 91.7% 문제)
2. 날짜는 본문에 한국어 표기 (헤더식 날짜는 질의 임베딩에 안 걸린다)
3. 인사말·서명·주소·전화 블록 제거 (서명 조각이 개체가 된다)
4. 문서 2,000자 이내 목표 — 청크 1개(1,200토큰)에 담기게
5. 집계 대상(품목·수량·단가)은 표 한 곳에 모은다 (행이 흩어지면 집계 질문이 틀린다)
6. 모르는 값은 추정해서 채우지 않는다

## 색인 규칙

1. `status: reviewed`인 문서만
2. 프론트메터 제거 후 `# {title}\n\n{본문}`으로 `POST /documents/text`
3. `file_source` = `id`
