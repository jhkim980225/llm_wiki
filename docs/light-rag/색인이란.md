# 색인(인덱싱)이란 — LightRAG 기준

색인 = 문서를 LightRAG에 넣어 **질의 가능한 상태로 만드는 작업**. 색인 안 된 문서는
그래프에 존재 자체가 없어서 질문해도 답변에 안 잡힌다. [파이프라인.md](wiki/파이프라인.md)의
⑥(전송)·⑦(내부 추출) 단계가 이것이다.

## 내부에서 벌어지는 일

문서 1건을 `POST /documents/text`로 던지면 LightRAG가 순서대로:

```
원문 텍스트
  │ ① 청킹 — 문서를 일정 크기 조각으로 분할
  ▼
  │ ② 개체·관계 추출 — LLM(LUNA)이 조각을 읽고
  │    "성진", "김종태", "발주했다" 같은 개체·관계를 뽑아
  │    그래프 노드·엣지로 만든다. SUMMARY_LANGUAGE 설정이
  │    여기서 쓰인다(미설정이면 영어로 뽑힘 — 실측으로 당함)
  ▼
  │ ③ 임베딩 — 조각을 벡터로 변환(embeddinggemma, 768차원).
  │    나중에 의미 검색용
  ▼
그래프 저장소 + 벡터 저장소에 기록 → 상태 processed
```

②에서 LLM이 문서당 여러 번 불리므로 **비용이 들고 느리다** — 우리 환경 실측
문서당 2~4분. ③은 사내 Ollama라 무료지만 직렬 처리라 병목이 여기서 생긴다.

## 문서 상태

| 상태 | 뜻 |
|---|---|
| pending | 대기열에 있음 |
| processing | ①~③ 진행 중 |
| processed | 색인 완료 — 질의에 잡힘 |
| failed | 실패 — 그래프에 없음. 삭제 후 재제출해야 함 |

`/lightrag` 화면(확인용)이나 `GET /documents`로 확인한다.

## 우리 파이프라인에서의 위치

```
원본 이메일 → 큐레이션 → wiki/ 문서(reviewed) → [색인] → LightRAG 그래프 → 질의응답
```

- 색인 도구: `scripts/lightrag-wiki-seed.py`(큐레이션 위키) · `scripts/lightrag-seed.py`(운영 위키)
- 색인 대상: `status: reviewed`인 문서만. 프론트매터는 벗겨내고 본문만 전송, `file_source = id`
- 현재 색인: 121건 (wiki 87 + 운영 위키 34), 전부 processed

## 주의 (전부 실측으로 당한 것 — 상세는 [운영.md](운영.md))

- **여러 건 동시 투입 금지.** 임베딩 서버가 직렬이라 대량 투입 시 60초 타임아웃 →
  파이프라인 전체 halt → 뒤에 줄 선 문서 전부 자동 취소(failed). 한 건
  processed/failed 확인 후 다음 건 제출이 유일하게 안전한 방식
- **삭제는 비동기.** failed 문서 지우고 바로 재제출하면 레이스로 문서가 그래프에서
  조용히 증발한다. `/documents`에서 사라진 것 확인 후 재제출
- **emptyDir.** 파드 재시작 = 색인 전멸, 전량 재색인 필요
- **같은 id 재색인 거부** ("already contains") — 갱신하려면 삭제 후 재제출.
  이 응답은 기존 문서가 failed여도 똑같이 나오므로 "이미 있음 = 성공"으로 착각하지 말 것
