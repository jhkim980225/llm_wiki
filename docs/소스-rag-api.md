# 소스 RAG API 연동 현황

2026-08-08 실측. 사내 3개 소스가 제공하는 질의응답 API의 응답 형태와, 우리가 그것을
어떻게 받아 쓰는지 정리합니다. 구조는 `docs/rag-architecture.md`, 개체 참조 설계는
`docs/superpowers/specs/2026-08-07-graph-ref-design.md`를 참조하십시오.

## 한 줄 요약

> 세 소스 모두 `{ answer, entities: [{name, type}] }` 형태로 응답합니다.
> `answer`는 화면에 그대로 쓰고, `entities`는 걸러서 개체 참조(GraphRef)에 쌓습니다.

## 1. 엔드포인트

| 소스 | 이름 | 엔드포인트 | 환경변수 |
|---|---|---|---|
| `ejkim` | 이메일 온톨로지 | `http://192.168.0.113:30311/ejkim/api/rag/ask` | `EJKIM_RAG_URL` |
| `kakao` | 카카오 지식그래프 | `http://192.168.0.114:30309/kakao/api/rag/ask` | `KAKAO_RAG_URL` |
| `seunghoon` | 승훈 온톨로지 | `http://192.168.0.113:30313/api/rag/ask` | `SEUNGHOON_RAG_URL` |

요청은 세 소스가 동일합니다.

```http
POST <엔드포인트>
Content-Type: application/json

{ "question": "성진 사업자등록번호" }
```

## 2. 응답 — 우리가 쓰는 두 필드

소스마다 부가 필드가 다르지만 **우리는 `answer`와 `entities`만 봅니다**
(`src/lib/rag/source-rag.ts`). 나머지는 무시하므로 저쪽이 늘려도 우리 쪽은 영향이 없습니다.

```jsonc
{
  "answer": "주식회사 성진의 사업자등록번호는 **211-88-58527**입니다.",
  "entities": [
    { "name": "주식회사 성진", "type": "organization" },
    { "name": "211-88-58527", "type": "businessNumber" }
  ]
}
```

소스별 전체 응답 키 (2026-08-08 실측):

| 소스 | 키 |
|---|---|
| `ejkim` | `answer` `entities` `evidence` `mails` `documents` `highlightRelations` `graph` `configured` `model` |
| `kakao` | `answer` `entities` `timing` `sparql` `rowCount` `nodes` `mode` `rows` `anchors` `anchorGroups` `evidence` `sources` `facts` |
| `seunghoon` | `answer` `entities` `question` `matches` |

`entities`가 없거나 비어 있어도 정상 동작합니다 — 빈 배열로 처리하고 답변만 씁니다.

## 6. 우리 쪽 필터 (`src/lib/graph-ref/entities.ts`)

`entities`를 그대로 저장하면 링크 제안이 본문 아무 데나 걸리므로 입구에서 거릅니다.

### 6.1 타입으로 차단 — 값·분류

문서로 만들 것이 없는 타입입니다. **이름을 보기 전에** 버립니다.

| type | 실측 예시 |
|---|---|
| `amount` | 5,958,700원 · 4,000,000원 · 15,000,000원 |
| `date` | 2025-04-18 · 2025-07-14 |
| `quantity` | 10ml · 5개 · 100g · 200개 |
| `contact` | 031-522-4858 |
| `period` | 2024년 |
| `process` | 제조 · 충진 · 소분 |
| `packaging` | 용기 · 라벨 · 단상자 |
| `formulation` | 크림 · 세럼 · 선크림 |
| `documentType` | 견적서 · 전성분 · 사업자등록증 · 문안 |

### 6.2 이름으로 차단

| 사유 | 실측 예시 |
|---|---|
| 괄호 불균형(문장 조각) | `라 한다)과 주식회사 성진` · `하 "갑"이라 한다)와 주식회사 성진` |
| 문장 조각(서술어 끝) | `저장통에 밀폐후 반제품실에 보관` |
| 일반 낱말(표 헤더) | `제조비` · `제조원` · `제품명` · `제품표준서` |
| 비개체 패턴(비용·파일·수량) | `생활화학제품 시험 검사비` · `화장품 제품/제형 개발비` |
| 나열 조각 | `화장품 3종 시제품 연구개발 및 생산(세럼, 크림, 마스크팩)` |

### 6.3 살리는 타입

`organization` · `person` · `product` · `material` · `brand` · `jobTitle` ·
`businessNumber` · `ingredient` · `case`

## 7. 수집 경로

`askSourceRag`를 타는 **모든 경로**가 자동으로 수집합니다 — 채팅(`/chat`),
AI 작성(`/ask`), WBS 주간일정 채움, FLOW 실행, 정합성 검증(`/verify`).

```
질문 → 소스 RAG API → { answer, entities }
                         ↓ cleanEntities로 거름
                      GraphRef upsert (fire-and-forget, 실패해도 답변을 막지 않음)
                         ↓
                본문에 그 이름이 나오면 [[링크]] + 타입 배지
                         ↓ 클릭
                문서 없으면 "그래프에서 문서 만들기" → 개체 그래프
```

같은 개체가 다시 나오면 `lastSeenAt`만 갱신하고 나머지는 덮지 않습니다 —
사람이 승격해 둔 문서를 나중 응답이 되돌리면 안 되기 때문입니다.

## 8. 정합성 검증 (2026-08-08 실측)

`/verify`로 같은 질문을 **RAG API**(A)와 **그래프 DB SPARQL 직조회**(B)에 동시에 던져
LLM이 소스별로 판정합니다. 질문 5개 전부 완주(17~21초), 15개 판정이 나왔습니다.

### 8.1 판정 집계

| 소스 | 일치 | 부분일치 | 판단불가 | 불일치 |
|---|---:|---:|---:|---:|
| ejkim | 0 | 3 | 2 | **0** |
| kakao | 2 | 2 | 1 | **0** |
| seunghoon | 2 | 2 | 1 | **0** |

**불일치(모순) 0건.** "판단불가"는 답이 틀렸다는 뜻이 아니라 SPARQL 원시 개체·관계
목록에 그 수치가 없어 대조할 수 없다는 뜻입니다 — API는 문서 본문까지 읽고 집계하는데
SPARQL 직조회는 개체·관계만 훑기 때문입니다.

### 8.2 소스가 서로 다르게 답한 것 — 시연에서 나올 질문

**코바상사 거래 건수·금액** (세 소스가 전부 다름)

| 소스 | 건수 | 금액 | 기준 |
|---|---:|---:|---|
| ejkim | 9건 | 238,133,008원 | 업무건별 최신 문서 금액 합산(견적 포함) |
| kakao | 9건 | 113,244,115원 | 수주·매출(입금) 기준 |
| seunghoon | 8건 | 104,460,656원 | 거래만, 견적 11건(278,558,390원) 제외 |

셋 다 맞습니다 — **집계 기준이 다릅니다**. 통합 답변이 이 차이를 표로 밝히고
"출처별 기준이 달라 일치하지 않습니다"라고 명시합니다. 숫자를 하나로 뭉개지 않는 것이
이 화면의 값어치입니다.

**정아라의 직함** (시점·출처에 따라 다름)

| 소스 | 직함 | 근거 |
|---|---|---|
| ejkim | 과장 | 메일 기준, 2026-07-16 마지막 확인. 과거 직책 포함 6건 |
| kakao | 연구원 | `정아라 → 직책 : 연구원` 관계 |
| seunghoon | 선임연구원 | 보완심사연기신청사유서, GMP 조직도 R&D 팀원 |

승진 이력이 있는 사람이라 시점에 따라 갈립니다. 통합 답변이 셋을 나란히 놓고
"현재 직함이 무엇인지는 확인되지 않음"으로 닫습니다.

**성진 직원 명단**

| 소스 | 답 |
|---|---|
| ejkim | 5명 (김윤서·김종태·정아라·최담선·이수연) |
| kakao | 4명 (이수연 없음) |
| seunghoon | 직원 명단 기록 없음 — 성진은 거래처·공급사로만 나타남 |

통합 답변이 "이수연 — 이메일 온톨로지에서만 확인됨"으로 갈라 적습니다.

### 8.3 일치한 것

- **성진 사업자등록번호 211-88-58527** — ejkim·kakao가 독립적으로 같은 번호.
  kakao는 SPARQL 직조회로도 확인되어 **일치** 판정
- **김종태 대표이사** — 세 소스 모두 대표/대표이사. seunghoon은 GMP 조직도로 뒷받침

### 8.4 읽는 법

- **일치** — API 답변의 핵심 주장이 SPARQL 원본에서 그대로 확인됨
- **부분일치** — 일부만 확인. 나머지는 원본에 없을 뿐 모순은 아님
- **판단불가** — 원본에 대조할 값 자체가 없음(주로 집계 수치). 답이 틀렸다는 뜻이 아님
- **불일치** — 원본과 모순. **이번 15건에는 없었습니다**

재현: `/graphwiki/verify`(사이드바에 없음, URL 직접 접근) 또는 `POST /api/verify`.

## 9. 저쪽 팀에 남은 요청

- **`uri` 제공** — 개체의 그래프 subject URI. 없으면 우리가 라벨로 조회하는데
  동명이인을 구분하지 못합니다. 필수는 아니고, 있으면 정확해집니다
- **seunghoon 추출 정제** — 계약서 원문 조각(`라 한다)과 주식회사 성진`)이 섞입니다.
  우리가 거르고 있어 급하지는 않습니다
- **kakao 응답 시간** — 평균 14.7초로 세 소스 중 가장 깁니다. 동시 호출이라
  전체 체감이 여기에 묶입니다
