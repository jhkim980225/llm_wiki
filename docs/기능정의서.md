# GraphWiki 기능정의서

작성일: 2026-08-04 · 최종 갱신: 2026-08-10 · 버전 0.67.0 기준
상세 설계 문서: `docs/superpowers/specs/2026-08-04-wiki-v2-design.md` · UI 표준: `docs/design.md`

## 1. 개요

GraphWiki는 사내 Fuseki 온톨로지를 위키 문서 형태로 가져와, 옵시디언처럼 `[[링크]]`로
문서 사이를 오가며 읽고 편집할 수 있는 웹 애플리케이션입니다. 개체를 그래프로 시각화하는
대신, 개체 하나를 문서 하나로 만들어 관계를 본문 링크로 표현하는 것이 핵심 설계입니다.

| 항목 | 내용 |
|---|---|
| 기술 스택 | Next.js 16 App Router · React 19 · TypeScript · Prisma + PostgreSQL |
| 외부 연동 | Fuseki (SPARQL, 읽기 전용) · 소스별 RAG API 3종 · LLM(OpenAI 호환 — 현재 `gpt-5.6-luna`, 사내 vLLM `qwen3-32b-finance`로 전환 가능) · 사내 Ollama (embeddinggemma, 의미검색 임베딩) · 사내 PlantUML 서버(다이어그램 렌더) |
| 인증 | 아이디/비밀번호 계정 인증(bcrypt · HMAC 세션 쿠키 · 감사 로그). 워크스페이스 다대다 + 역할 |
| 배포 환경 | 사내 k8s `jh-wiki-graph` 네임스페이스, NodePort 31900 |
| 데이터 규모 | 적재 문서 179,910건(이메일 · 카카오 · 승훈 3소스) + 사람·에이전트 작성 문서 |
| 현재 용도 | 사내 데모 / PoC |

## 2. 구현 완료 기능

### 2.1 위키 문서 관리

| 기능 | 설명 |
|---|---|
| 문서 조회 | `/wiki/<slug>` 경로에서 마크다운을 렌더링합니다. `[[위키링크]]`는 앵커로 변환되며 XSS 이스케이프를 거칩니다. |
| 문서 편집 | 마크다운 편집기를 제공합니다. 낙관적 잠금을 사용하여 충돌 시 409 응답과 함께 diff를 보여주고 사용자가 병합 여부를 결정합니다. |
| 리비전 이력 | 편집할 때마다 리비전을 저장합니다. 이력 화면에서 줄 단위 diff를 비교하고 이전 버전으로 되돌릴 수 있습니다. |
| 백링크 | 문서 저장 시 링크 관계를 자동으로 갱신하며, 문서 하단에 이 문서를 가리키는 문서 목록을 표시합니다. 적재본은 백링크가 수백~수천 건이라(실측 6,186) **기본 접힘 토글**입니다. |
| 이름 변경 | slug를 변경하면 해당 문서를 가리키던 모든 `[[링크]]`가 자동으로 수정됩니다. |
| 문서 생성 | 존재하지 않는 문서에 접근하면 그 자리에서 새로 만들 수 있습니다. 삭제된 slug를 다시 사용하면 기존 문서를 복원합니다. |
| 검색 | Ctrl+K로 검색창에 진입합니다. 한국어 특성에 맞춘 부분 문자열 매칭이며, 제목 정확 일치부터 본문 포함까지 5단계 랭킹을 적용합니다. 제목·요약 검색은 약 40ms, 본문 포함 검색은 약 320ms가 소요됩니다. |
| 링크 잇기 | 편집 중 버튼을 누르면 본문에 이름이 등장하는 다른 문서를 찾아 `[[링크]]`로 감싼 결과를 diff로 미리 보여주고, 사용자가 적용 여부를 선택합니다. AI 작성·FLOW 생성 문서에도 저장 전 같은 규칙이 자동으로 적용됩니다. 규칙(2026-08-09~10 개정): ① 후보 100개를 뽑되 **개체명(GraphRef 등록부에 있는 이름)을 먼저 남깁니다** — 예전엔 제목 긴 순으로만 잘라 메일 제목·파일명이 자리를 다 먹고 사람·업체 이름이 통째로 밀려났습니다. ② 같은 이름이 여러 소스에 있으면(같은 사람이 이메일·카톡에 모두 기록된 경우) **연결이 가장 많은 문서**로 잇고, 1·2위가 같으면 걸지 않습니다. ③ 문장에서는 첫 출현만, **표에서 칸 전체가 이름인 칸은 매 줄** 링크합니다(담당자·거래처 열). 97,000건 문서 기준 약 45ms가 소요됩니다. |

### 2.2 화면 (UI)

`docs/design.md`가 UI 표준입니다. 차분한 다크 단일 테마, Pretendard Variable +
JetBrains Mono, lucide-react 아이콘, teal 액센트(`#2DD4BF`)의 전문 문서 도구 스타일이며
좌측 내비게이션(196px) · 문서 트리(290px) · 본문(최대 1040px, 좌측 정렬)의 3단 구성입니다.

| 기능 | 설명 |
|---|---|
| 좌측 내비게이션 | 홈 · 그래프 · AI 작성 · 휴지통 메뉴와 하단 설정. 문서 트리는 상시 표시되며, 로고 옆 햄버거를 누르면 전체가 아이콘 전용으로 접히고 `>>`로 복귀합니다(상태 기억). 선택 항목은 좌측 액센트 인디케이터로 표시합니다. (문서·도우미·소스 탭은 2026-08-06 제거) |
| 그래프 뷰 | `/graph`에서 문서를 노드로, `[[위키링크]]`를 에지로 하는 연결 그래프를 표시합니다(옵시디언 그래프 뷰 방식). 포스 레이아웃(결정적 시드) · 휠 줌 · 드래그 팬 · 화면 맞춤을 지원하며, 노드를 선택하면 우측 패널에 유형 · 링크 수 · 요약 · 수정 이력이 표시되고 문서로 이동할 수 있습니다. 전체 문서가 수만 건이라 연결 상위 200개만 그립니다. |
| 문서 트리 | 폴더/문서 아이콘과 chevron으로 계층을 표현합니다. 생성 · 이름 변경 · 이동 · 삭제와 **드래그앤드롭 이동**(문서→폴더, 폴더→폴더, 빈 공간에 놓으면 최상위로)을 지원합니다. 브라우저 기본 드래그 프리뷰는 제거했습니다. |
| 검색 | 트리 상단 검색창(Ctrl+K). 두 글자 이상 입력하면 결과가 트리 자리에 표시됩니다. |
| 새 문서 | 노션처럼 대화상자 없이 즉시 생성됩니다(Ctrl+N). 제목 "제목을 입력하세요"로 저장된 뒤 편집 모드로 열립니다. |
| 탭 | 열어 본 문서가 상단 탭(44px)으로 유지됩니다(최대 8개, localStorage). 활성 탭은 하단 액센트 라인으로 표시합니다. |
| 문서 상세 | 제목 아래 metadata row(type · updated · author · links)로 표시합니다. 끊긴 링크는 amber 배지입니다. |
| 문서 사이드 챗 | 문서 보기 화면 우측 토글 패널(탭바 "질문" 버튼)에서 **현재 문서 본문을 컨텍스트로** 질문·답변합니다. 대화는 저장하지 않으며(일회성), 다른 문서로 이동하면 초기화됩니다. |
| 문서 편집기 | 서식 툴바(제목·목록·체크·인용·코드·위키링크·이미지·표), 태그·별칭 pill 편집, 상태(초안/발행) 토글, 저장 상태 표시, Ctrl+S 저장. 우측 문서 정보 패널에서 버전 히스토리 · 복제 · .md 내보내기 · 삭제를 실행합니다. 삭제는 브라우저 알럿이 아닌 앱 공통 확인 대화상자를 사용하며, 입력란에 포커스가 없을 때 Delete 키로도 호출됩니다(문서 보기 화면 동일). 낙관적 잠금(409 diff)은 기존과 동일합니다. |
| 개체 요약 카드 | 온톨로지 적재 개체 문서(type=entity)는 관계를 모두 나열해 링크가 수십~수백 개입니다(메일 1건 실측 나감 54·들어옴 59). 본문 위에 **핵심 관계만 추린 요약 카드**를 얹어 누가·무엇과 연결됐는지 먼저 보이게 합니다. 수치·날짜·전화번호 같은 값 노드(`30 mL · 용량`, `02-2092-3721`)는 제외하고, 값이 절반을 넘는 관계(`hasBusinessFact` 등)는 통째로 뺍니다. 관계당 4개·최대 8개 관계까지 보여 주고 나머지는 '외 N개'로 셉니다. 저장된 본문은 그대로 두고 표시할 때만 계산하므로 재적재가 필요 없습니다. (2026-08-08) |
| 긴 절 접기 | 생성 문서의 `## 참고`(근거 링크 목록, 실측 33개)와 적재본의 `## 이 문서를 가리키는 관계`(역참조 목록, 견적서 파일이 수십 개씩 쌓입니다)는 **기본 접힘 토글**로 표시합니다. 절 안의 `###` 소제목까지 통째로 접습니다. 제목을 누르면 펼쳐지고, 본문 끝이 링크 목록으로 덮이지 않습니다. 저장된 본문은 그대로이며 표시할 때만 감쌉니다. (2026-08-09) |
| 적재본 요약 (열람 시 생성) | 적재 개체 문서 상단에 **LLM이 쓴 2~4문장 요약**을 보여 줍니다. 적재본이 18만 건이라 미리 만들면 토큰을 감당할 수 없으므로 **사람이 그 문서를 열었을 때만** 만들고 `Page.brief`에 캐시합니다. 이미 있으면 다시 만들지 않고, 재적재로 본문이 바뀌면 `briefHash`가 어긋나 다음 열람에서 자동으로 새로 만듭니다. 대상은 `lastEditSource='ontology'`인 문서뿐이며(사람이 쓴 문서는 제외), 본문은 3,000자까지만 보내고 위키링크는 표시명만 남겨 토큰을 아낍니다. 요약 저장은 version을 올리지 않습니다(가시 필드가 아님). 같은 문서를 동시에 열면 진행 중인 것 하나만 생성합니다. (2026-08-09) |
| 페이지 전환 | 클라이언트 라우팅 + 180ms fade 전환. `prefers-reduced-motion`을 존중합니다. |
| PlantUML 다이어그램 | 본문의 ` ```plantuml ` 코드 블록을 그림(SVG)으로 렌더합니다. 간트 차트(@startgantt)·시퀀스 등 PlantUML 전 문법을 지원하며, 사내 PlantUML 서버(도커/k8s 배포)가 그림을 그리고 앱의 `/api/plantuml` 프록시를 거쳐 표시됩니다. 다이어그램이 텍스트로 저장되므로 사람·LLM 모두 편집할 수 있고, FLOW 템플릿에 넣으면 자동 생성 문서에도 값이 채워진 다이어그램이 들어갑니다(주간업무내역 양식에 주간 일정 간트 예시 포함). 문법 오류 시 PlantUML의 오류 안내 그림이 그 자리에 표시됩니다. 간트에는 **공통 서식(글꼴·구분 헤더·휴일 음영)을 렌더러가 자동으로 얹어** 문서마다 서식을 베끼지 않아도 같은 모양이 나옵니다 — 문서가 `<style>`을 직접 쓴 경우에는 그쪽을 존중합니다. (2026-08-08) |
| 주간 일정 WBS 격자 | 본문의 ` ```wbs ` 블록에 **평범한 마크다운 표**(WBS·업무·담당·시작·종료·기간·진행)를 넣으면 **작업 정보와 일정 막대가 한 판에 붙은 WBS 간트**로 그려집니다. 날짜 열은 표의 날짜에서 자동 계산하며 주말은 뺍니다. 헤더는 **달 → 주차 → 요일·일자 3단**입니다(레퍼런스 WBS 간트의 Phase → Week → 요일 구성과 동일). 날짜가 자리표시자뿐이면 날짜 열 없이 왼쪽 표만 한 단으로 냅니다. 대분류 행(코드에 점이 없고 날짜가 없는 줄)은 구분 행으로, 막대 색은 대분류 번호별로, 진행률은 값 구간별 색으로 표시합니다. 종료일이 비면 시작일+기간(영업일)으로 채웁니다. 저장되는 것은 표 그대로라 편집·검색·LLM 생성 모두 평범한 표로 다룹니다. 주간업무내역 양식이 이 형식을 쓰며, **양식에는 자리표시자만 두고 실제 조직·업무·인물은 FLOW 지시문이 갖습니다**(양식은 형식, 내용은 FLOW). (2026-08-08) |
| 온보딩(홈) | 좌측 정렬 사용 가이드 — 사이드바 각 메뉴(문서·그래프·AI 작성·휴지통·설정)의 역할을 설명하는 클릭 가능한 목록. 누르면 해당 화면으로 이동합니다. |
| LightRAG 테스트(실험) | **bench 계정 전용** — 사이드바 `LightRAG` 탭(`/lightrag`)에서 클러스터에 배포된 LightRAG PoC 서버에 질문을 보내 기존 AI 작성·채팅 답변과 비교합니다. 검색 모드 5종(hybrid·local·global·naive·mix) 선택, 앱 서버 프록시(`/api/lightrag`) 경유로 API 키는 서버에만 둡니다. 색인은 `scripts/lightrag-seed.py`, 기존 RAG와의 비교는 `scripts/lightrag-bench.py`(15문항 자동 실행, 결과 `docs/light-rag/`)로 수행하며, 실험 종료 시 탭·화면·파드를 함께 제거합니다. (2026-08-20) |
| 사용자 가이드(도움말) | 글로벌 메뉴 하단 `도움말` 또는 홈의 `가이드` 항목으로 `/guide` 화면을 엽니다. `docs/manual/사용자-매뉴얼.md`를 빌드 시점에 그대로 렌더하므로 매뉴얼이 단일 소스이며, 화면 캡처도 함께 표시됩니다. (2026-08-13) |
| 휴지통 | 삭제한 문서·폴더가 **7일간 보관**된 뒤 자동 영구 삭제됩니다(휴지통 조회 시점 lazy purge). 복원 시 원래 위치가 삭제된 경우 최상위로 복원되며, 즉시 비우기도 지원합니다. |
| 설정(상태) | 그래프 연결 상태, 온톨로지 적재 현황, LLM 백엔드 상태를 한 화면에서 확인하고 수동으로 재점검할 수 있습니다. |
| 로그인 | 아이디(loginId)/비밀번호 인증(`/login`). 비밀번호는 bcrypt(cost 12), 5회 연속 실패 시 10분 잠금, 로그인 상태 유지(30일, 미선택 8시간), 감사 로그(성공·실패·잠금·로그아웃·비밀번호 변경) 기록. 세션은 HMAC 서명 쿠키 + `UserSession` 테이블(SHA-256 해시, 폐기 가능). 계정 생성은 관리자 API로만 하며(가입 없음), 초기 비밀번호는 전화번호 뒷자리 운용 방침에 따라 관리자 지정 값을 정책 검사 없이 허용하고 변경을 강제하지 않습니다(사용자가 직접 바꿀 때만 8자·2종류 정책 적용, 2026-08-20). 개발 환경 시드로 test/test 계정이 만들어집니다(운영 제외). 성공·잠금·네트워크 오류는 전역 토스트로 피드백하고, 설정 모달에서 로그아웃할 수 있습니다. 워크스페이스(다대다, OWNER·WORKSPACE_ADMIN·EDITOR·VIEWER)는 로그인 시 기본 워크스페이스로 자동 진입, 기본이 없고 여럿이면 선택 UI가 표시됩니다. |

### 2.3 온톨로지 적재

| 기능 | 설명 |
|---|---|
| 대량 적재 | 설정→상태 탭의 소스별 '가져오기' 버튼 또는 `POST /api/ontology`로 실행합니다. 개체는 문서로, 관계는 `[[링크]]`로 변환됩니다. 실측 기준 24,822개 개체를 36초에 적재했으며 끊어진 링크는 0건입니다. **분신 병합(2026-08-07)**: 제목이 같고 서로 연결돼 있으며 한쪽만 속성이 없는 노드 쌍(이메일 온톨로지의 Email·BusinessCase 분할)은 본문 있는 문서 하나로 합쳐 적재합니다. |

| 부분 적재 | 적재 건수를 제한해도 관계 대상 문서의 표시명을 추가로 가져와 링크가 끊어지지 않도록 처리합니다. |
| 다중 소스 | 소스별 폴더와 slug 접두사로 이름 충돌을 방지합니다. 소스 간 어휘 차이는 `lib/ontology/source.ts` 한 곳에서 흡수합니다. |

### 2.4 LLM 연동

| 기능 | 설명 |
|---|---|
| 채팅 (`/chat`) | 일반 대화형 채팅(대화 이력 영속화). 대화는 사용자·워크스페이스 스코프로 `ChatConversation`/`ChatMessage`에 저장되며, 좌측 목록에서 이전 대화를 이어가거나 삭제할 수 있습니다. 사내 사실 질문에는 **읽기 전용 RAG 도구**(위키 검색·의미검색·열람 + 소스별 전용 RAG API 동시 질의)를 LLM이 스스로 호출해 근거를 수집합니다. 여러 소스의 결과는 소스별 나열 없이 **주제 단위로 통합**해 답하며, 항목마다 **근거 문서 하이퍼링크**(`[[slug\|표시명]]` — 온톨로지 적재 문서로 이동, 출처 유형 배지 이메일/카톡/문서)를 답니다. 지어낸 링크는 저장 전에 평문으로 강등됩니다. 쓰기 도구는 없어 위키를 고치지 않습니다. | 지식 그래프 동시 조회 | Fuseki 3개 소스(ejkim · seunghoon · kakao)를 한 번에 조회합니다. 소스별 성공/실패를 구분하여 반환하고, 응답이 없는 소스는 60초간 조회를 건너뜁니다. |
| 2단계 그래프 검색 | 먼저 라벨(이름)로 검색하고, 결과가 없으면 리터럴 본문까지 검색합니다. |
| 그래프 RAG (`/ask`) | 질문 하나로 용어 추출 → **근거 3갈래 동시 수집** → 문서 작성을 고정 순서로 수행합니다. 근거는 **세 소스 모두 전용 RAG API**(질문 원문 전달 → 자연어 답변 수신, 소스별 `*_RAG_URL` env)로 수집하고 최종 LLM이 요약 통합합니다. API가 없는 소스가 추가되면 SPARQL 직조회로 동작합니다. 위키는 용어가 제목·요약·본문에 나오는 문서의 발췌를 근거로 쓰며(사람이 쓴 문서 우선), 참고 절에 `[[링크]]`로 남습니다. 결과는 NDJSON 스트리밍으로 단계별 전달되며, **작성 완료 시 자동으로 볼트에 저장**됩니다(이름 충돌 시 접미사로 회피). 본문 문장·표 항목에는 **근거 문서 하이퍼링크**(`[[slug\|표시명]]` + 출처 배지 이메일/카톡/문서)가 달립니다 — API 답변에 제목이 등장하는 실존 온톨로지 문서만 링크하며, 지어낸 링크는 저장 전 평문으로 강등됩니다(2026-08-07). |

| FLOW (`/flow`) | 프롬프트+템플릿 문서+저장 폴더를 **배치 작업으로 등록**하면 매주 지정 요일·시각에 자동 실행되어 결과 문서가 폴더에 쌓입니다. 수동 실행·활성/중지 토글·실행 이력을 제공합니다. 실행 이력의 결과 문서를 누르면 **상세창**이 열려 그 문서를 만든 지시문·템플릿·저장 폴더·주기·실행 시각을 보여 주고 '문서로 가기'로 이동합니다 — 목록만으로는 결과가 왜 그렇게 나왔는지 알 수 없기 때문입니다. 템플릿 문서와 **저장 폴더 모두 드롭다운으로 고릅니다** — 직접 입력이면 오타 하나가 새 폴더를 만들어 결과 문서가 엉뚱한 곳에 쌓입니다(목록을 못 받으면 직접 입력으로 되돌아갑니다). 스케줄은 k8s CronJob이 10분 간격으로 due 작업을 실행하는 방식이며(토큰 보호 tick API), 삭제는 soft delete입니다. (2026-08-08) |
| 개체 종류 필터 | 그래프 칩이 **종류(개체 계층)와 관계 두 축**입니다. 종류는 문서·메일·인물·조직·직함 등 rdf:type 기준이고, 관계와 함께 걸면 둘 다 만족하는 이웃만 그립니다. 하나라도 고르면 상한이 50으로 올라갑니다. (2026-08-08) |
| 개체 관계 그래프 | 개체 문서 상단 **[그래프]** 토글로 그 개체를 중심에 둔 1홉 관계도를 봅니다. Postgres 사본이 아니라 **그래프 DB를 직접 조회**하므로 갓 만든 문서에서도 관계가 보입니다. 이웃이 많은 개체(실측: 사람 1명에 198개)는 화면이 읽히지 않으므로 **관계 종류별로 돌아가며 10개까지만** 그리고, 툴바에 `이웃 198개 중 10`으로 감춘 수를 표시합니다. 문서 본문의 관계 목록은 자르지 않습니다. 외부(LLM)가 만든 질의는 실행 전 읽기 전용 검사(SELECT·CONSTRUCT만, 다중 구문 거부, LIMIT 강제)를 통과해야 합니다. (2026-08-07) 개체 문서는 기본으로 좌측 문서 · 우측 그래프 분할 화면이 열리며, [그래프] 버튼으로 전체 그래프 보기와 분할 보기를 오갑니다. 분할 폭이 좁은 화면(1700px 미만)에서는 인스펙터 패널을 접습니다. (2026-08-08) |
| 정합성 검증 (`/verify`) | 같은 질문을 **소스별 전용 RAG API**와 **그래프 DB SPARQL 직조회**에 동시에 던져 결과를 나란히 비교하고, LLM이 소스별 정합성(일치·부분일치·불일치·판단불가)을 판정합니다. API 3소스의 답변을 하나로 합친 **통합 답변**(소스 간 차이 명시)도 함께 제공하며, 실행된 SPARQL 질의문도 표시합니다. RAG API 도입 근거 확보용 테스트 화면입니다. (2026-08-07 사이드바 메뉴에서 제거 — URL 직접 접근만 가능) |

## 4. 알려진 제약 사항

- ~~대형 폴더의 이름 변경은 약 45초가 소요됩니다.~~ **해결됨(2026-08-05):** 경로 캐시 컬럼(categoryPath/wikiPath/depth)을 제거하고 folderId 기반 온디맨드 계산으로 전환하여 폴더 이름 변경이 폴더 행 1건 갱신(~28ms)으로 끝난다.
- 그래프 RAG의 문서 작성 단계는 약 210초가 걸립니다. 32B 모델의 생성 속도가 원인이며, 스트리밍으로 체감 대기를 완화하고 있습니다.
- 사내 vLLM은 구조화 출력(guided decoding)을 지원하지 않아 평문 응답을 직접 파싱하고 zod로 검증합니다. 검증은 **개수로 실행을 죽이지 않습니다** — 검색어가 0개여도(2026-08-08 FLOW 실패 사례) 진행하고, 5개를 넘으면 앞에서 자릅니다. 근거의 주력인 소스 RAG API는 질문 원문을 따로 받으므로 검색어가 없어도 문서는 작성됩니다.
- qwen3 모델은 thinking 모드를 반드시 꺼야 합니다. 켜져 있으면 호출당 3~10배 느려집니다.
- 개발 PC(VPN)에서는 kakao Fuseki에 접근할 수 없습니다(NetworkPolicy 미허용). 클러스터 내부에서는 정상 연결됩니다.
- **적재 문서의 속성 표가 깨져 있습니다(179,910건 중 32,015건).** 적재기가 속성 행을 구울 때 파이프만 이스케이프하고 줄바꿈은 처리하지 않아, 메일 본문 리터럴(`bodyPreview`·`bodyText`)처럼 여러 줄인 값에서 표가 첫 줄에 끊기고 뒤따르는 `filename`·`sentAt` 행이 평문 문단으로 떨어집니다. 고치려면 값의 줄바꿈을 `<br>`로 바꾸고 **전량 재적재**가 필요합니다(저장된 본문 자체가 깨진 상태라 코드 수정만으로는 반영되지 않음).
- 개체 그래프를 크게 끌면 탭이 죽던 문제(“This page couldn't load”)는 해결됐습니다(2026-08-09). 드래그 중 이동마다 React 상태를 갱신해 DOM 2만 개짜리 적재 문서 전체가 매번 재계산되던 것이 원인이었고, 지금은 SVG 변환만 직접 바꾸고 손을 뗄 때 한 번만 상태에 반영합니다.
- Fuseki 질의 경로는 `/{dataset}/sparql`입니다. `/query` 경로는 405를 반환합니다.
