# GraphWiki 기능정의서

작성일: 2026-08-04 · 버전 0.13.0 기준
상세 설계 문서: `docs/superpowers/specs/2026-08-04-wiki-v2-design.md` · UI 표준: `docs/design.md`

## 1. 개요

GraphWiki는 사내 Fuseki 온톨로지를 위키 문서 형태로 가져와, 옵시디언처럼 `[[링크]]`로
문서 사이를 오가며 읽고 편집할 수 있는 웹 애플리케이션입니다. 개체를 그래프로 시각화하는
대신, 개체 하나를 문서 하나로 만들어 관계를 본문 링크로 표현하는 것이 핵심 설계입니다.

| 항목 | 내용 |
|---|---|
| 기술 스택 | Next.js 16 App Router · React 19 · TypeScript · Prisma + PostgreSQL |
| 외부 연동 | Fuseki (SPARQL, 읽기 전용) · 사내 vLLM (qwen3-32b-finance, OpenAI 호환) · 사내 Ollama (embeddinggemma, 의미검색 임베딩) |
| 인증 | 선택적 공유 비밀번호 게이트 (`APP_PASSWORD`). 미설정 시 공개(단일 워크스페이스) |
| 배포 환경 | 사내 k8s `jh-wiki-graph` 네임스페이스, NodePort 31900 |
| 데이터 규모 | 문서 97,015건 (이메일 온톨로지 72,186건 · 승훈 온톨로지 24,822건) |
| 현재 용도 | 사내 데모 / PoC |

## 2. 구현 완료 기능

### 2.1 위키 문서 관리

| 기능 | 설명 |
|---|---|
| 문서 조회 | `/wiki/<slug>` 경로에서 마크다운을 렌더링합니다. `[[위키링크]]`는 앵커로 변환되며 XSS 이스케이프를 거칩니다. |
| 문서 편집 | 마크다운 편집기를 제공합니다. 낙관적 잠금을 사용하여 충돌 시 409 응답과 함께 diff를 보여주고 사용자가 병합 여부를 결정합니다. |
| 리비전 이력 | 편집할 때마다 리비전을 저장합니다. 이력 화면에서 줄 단위 diff를 비교하고 이전 버전으로 되돌릴 수 있습니다. |
| 백링크 | 문서 저장 시 링크 관계를 자동으로 갱신하며, 문서 하단에 이 문서를 가리키는 문서 목록을 표시합니다. |
| 이름 변경 | slug를 변경하면 해당 문서를 가리키던 모든 `[[링크]]`가 자동으로 수정됩니다. |
| 문서 생성 | 존재하지 않는 문서에 접근하면 그 자리에서 새로 만들 수 있습니다. 삭제된 slug를 다시 사용하면 기존 문서를 복원합니다. |
| 검색 | Ctrl+K로 검색창에 진입합니다. 한국어 특성에 맞춘 부분 문자열 매칭이며, 제목 정확 일치부터 본문 포함까지 5단계 랭킹을 적용합니다. 제목·요약 검색은 약 40ms, 본문 포함 검색은 약 320ms가 소요됩니다. |
| 링크 잇기 | 편집 중 버튼을 누르면 본문에 이름이 등장하는 다른 문서를 찾아 첫 출현을 `[[링크]]`로 감싼 결과를 diff로 미리 보여주고, 사용자가 적용 여부를 선택합니다. 97,000건 문서 기준 약 45ms가 소요됩니다. |

### 2.2 화면 (UI)

`docs/design.md`가 UI 표준입니다. 차분한 다크 단일 테마, Pretendard Variable +
JetBrains Mono, lucide-react 아이콘, teal 액센트(`#2DD4BF`)의 전문 문서 도구 스타일이며
좌측 내비게이션(196px) · 문서 트리(290px) · 본문(최대 1040px, 좌측 정렬)의 3단 구성입니다.

| 기능 | 설명 |
|---|---|
| 좌측 내비게이션 | 홈 · 문서 · 그래프 · AI 작성 · 도우미 · 소스 메뉴와 하단 설정. 선택 항목은 좌측 액센트 인디케이터로 표시합니다. 1280px 미만에서는 아이콘 전용으로 축소됩니다. |
| 그래프 뷰 | `/graph`에서 문서를 노드로, `[[위키링크]]`를 에지로 하는 연결 그래프를 표시합니다(옵시디언 그래프 뷰 방식). 포스 레이아웃(결정적 시드) · 휠 줌 · 드래그 팬 · 화면 맞춤을 지원하며, 노드를 선택하면 우측 패널에 유형 · 링크 수 · 요약 · 수정 이력이 표시되고 문서로 이동할 수 있습니다. 전체 문서가 수만 건이라 연결 상위 200개만 그립니다. |
| 문서 트리 | 폴더/문서 아이콘과 chevron으로 계층을 표현합니다. 생성 · 이름 변경 · 이동 · 삭제와 **드래그앤드롭 이동**(문서→폴더, 폴더→폴더, 빈 공간에 놓으면 최상위로)을 지원합니다. 브라우저 기본 드래그 프리뷰는 제거했습니다. |
| 검색 | 트리 상단 검색창(Ctrl+K). 두 글자 이상 입력하면 결과가 트리 자리에 표시됩니다. |
| 새 문서 | 노션처럼 대화상자 없이 즉시 생성됩니다(Ctrl+N). 제목 "제목을 입력하세요"로 저장된 뒤 편집 모드로 열립니다. |
| 탭 | 열어 본 문서가 상단 탭(44px)으로 유지됩니다(최대 8개, localStorage). 활성 탭은 하단 액센트 라인으로 표시합니다. |
| 문서 상세 | 제목 아래 metadata row(type · updated · author · links)로 표시합니다. 끊긴 링크는 amber 배지입니다. |
| 페이지 전환 | 클라이언트 라우팅 + 180ms fade 전환. `prefers-reduced-motion`을 존중합니다. |
| 온보딩 | 빈 화면은 좌측 정렬 "GraphWiki 시작하기" + action list + 단축키 안내입니다. |
| 휴지통 | 삭제한 문서·폴더가 **7일간 보관**된 뒤 자동 영구 삭제됩니다(휴지통 조회 시점 lazy purge). 복원 시 원래 위치가 삭제된 경우 최상위로 복원되며, 즉시 비우기도 지원합니다. |
| 설정(상태) | 그래프 연결 상태, 온톨로지 적재 현황, LLM 백엔드 상태를 한 화면에서 확인하고 수동으로 재점검할 수 있습니다. |
| 로그인 | 이메일/비밀번호 계정 인증(`/login`). 회원가입 · 로그인 상태 유지(30일) · 필드 검증 · 오류 표시를 지원하며, 미인증 접근은 전부 로그인 화면으로 이동합니다. 비밀번호는 scrypt 해시로 `User` 테이블에 저장하고, 세션은 HMAC 서명 쿠키(서버 상태 없음)입니다. |

### 2.3 온톨로지 적재

| 기능 | 설명 |
|---|---|
| 대량 적재 | `/sources` 화면 또는 `POST /api/ontology`로 실행합니다. 개체는 문서로, 관계는 `[[링크]]`로 변환됩니다. 실측 기준 24,822개 개체를 36초에 적재했으며 끊어진 링크는 0건입니다. |
| 편집 보호 | 사람이나 에이전트가 수정한 문서는 재적재 시 덮어쓰지 않고 건너뜁니다. |
| 부분 적재 | 적재 건수를 제한해도 관계 대상 문서의 표시명을 추가로 가져와 링크가 끊어지지 않도록 처리합니다. |
| 다중 소스 | 소스별 폴더와 slug 접두사로 이름 충돌을 방지합니다. 소스 간 어휘 차이는 `lib/ontology/source.ts` 한 곳에서 흡수합니다. |

### 2.4 LLM 연동

| 기능 | 설명 |
|---|---|
| 채팅 도우미 | `/chat`에서 LLM이 9종의 도구(검색 · **의미검색** · 읽기 · 생성 · 수정 · 이동 · 삭제 · 링크 편집 · 그래프 조회)로 위키를 직접 편집합니다. 의미검색 도구로 단어가 안 겹쳐도 뜻이 가까운 문서를 근거로 끌어옵니다. |
| 지식 그래프 동시 조회 | Fuseki 3개 소스(ejkim · seunghoon · kakao)를 한 번에 조회합니다. 소스별 성공/실패를 구분하여 반환하고, 응답이 없는 소스는 60초간 조회를 건너뜁니다. |
| 2단계 그래프 검색 | 먼저 라벨(이름)로 검색하고, 결과가 없으면 리터럴 본문까지 검색합니다. |
| 그래프 RAG (`/ask`) | 질문 하나로 용어 추출 → **그래프 3개 소스 + 위키 문서 동시 조회** → 근거 수집 → 문서 작성을 고정 순서로 수행합니다. 위키는 용어가 제목·요약·본문에 나오는 문서의 발췌를 근거로 쓰며(사람이 쓴 문서 우선), 참고 절에 `[[링크]]`로 남습니다. 결과는 NDJSON 스트리밍으로 단계별 전달되며, **작성 완료 시 자동으로 볼트에 저장**됩니다(이름 충돌 시 접미사로 회피). |
| 백엔드 전환 | 기본은 사내 vLLM이며, 환경 변수 변경만으로 Ollama로 전환할 수 있습니다. 채팅 화면 배지로 현재 상태를 확인할 수 있습니다. |

### 2.5 API 목록

### 2.6 테스트

vitest 기준 18개 파일, 185개 테스트가 있습니다. 순수 함수 모듈(링크 파싱 · slug · 렌더링 ·
diff · 온톨로지 변환 · 그래프 빌드/레이아웃), DB 모듈(저장 · 이름 변경 · 트리 · 링크 잇기), **API Route Handler
회귀 테스트**(문서 CRUD · 낙관적 잠금 409 · 이동 · 폴더 순환 400 · 트리 · 검색 랭킹), 그리고
**UI 컴포넌트 테스트**(디자인 시스템 프리미티브 — 버튼/사이드바/트리 행/탭/온보딩 액션의
상태·클래스·이벤트·로케일 포맷)를 커버합니다. 컴포넌트 테스트 환경은 happy-dom +
@testing-library/react이며 `.test.tsx` 파일 상단 도크블록으로 DOM 환경을 켭니다. FileTree·
PageView 등 상태가 많은 컴포넌트와 E2E는 아직 없습니다.

## 4. 알려진 제약 사항

- ~~대형 폴더의 이름 변경은 약 45초가 소요됩니다.~~ **해결됨(2026-08-05):** 경로 캐시 컬럼(categoryPath/wikiPath/depth)을 제거하고 folderId 기반 온디맨드 계산으로 전환하여 폴더 이름 변경이 폴더 행 1건 갱신(~28ms)으로 끝난다.
